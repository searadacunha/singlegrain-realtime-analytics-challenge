| pii_in_properties | Field-level policy at the gate: tokenise (keyed hash per tenant) or drop according to the tenant's allow-list before the event reaches logs, metric labels, dashboards or exports. Logs carry event_id and tenant only. This report prints field names, never values. | Test or role addresses, e-mails inside URLs, order numbers that look like phone numbers. The opposite error matters more: names and free text that no pattern can see. |
| schema_variant | Accept and normalise through a versioned alias map, keep the original payload, count events per tenant and variant. The SDK cannot change, so the pipeline adapts. A missing received_at is stamped at the new edge. | An alias map can mis-map a tenant's own custom property that happens to share a legacy name. Aliases must be tied to known SDK versions. |
| missing_tenant | Quarantine. In the target design the edge derives the tenant from the SDK write key, never from the payload, and a payload tenant that disagrees is quarantined too. | None for the detection. Any attempt to guess the tenant can leak one customer's visitors into another customer's dashboard. |
| malformed_json | Quarantine the raw bytes with a reason code and count them. The consumer acknowledges the record and moves on: one poison record must never block a shard. | None for the detection. | late_arrival | Accept.
